# Closed October implementation paths

The [disposition matrix](matrix.tsv) records the nine reopening decisions,
including source commit, report URL, correctness, cost, quality, source
modules, risk and default behavior. Peak tracked numbers in individual
harnesses include their resident controls and original model. They cannot
be interpreted as the incremental cost of a stable feature. The
[branch inventory](../2026-11-21-inventory/README.md) supplies individual
test paths, raw artifact hashes and related implementation commits.

Seven hypotheses failed their frozen admission criteria. Rotated activation
preparation passed its operator gate, but the selected Qwen model lacks the
rotation. Soft-MTP lacks a compatible trained head and observed proposal
acceptance. The November work preserves all nine records. None of those
outcomes justifies a production change.

Selected-Q4 execution remains a measured operator with supplied indices.
C4 asks whether processing an existing sparse vector pays after charging
compaction and layout ownership. C1 tests reuse across tokens in the
existing target verifier, which requires different dataflow from the
closed multirow gate/up sweep. D1 can remeasure copy-oriented speculation
if the new target changes measured verification costs. Each has its own
gate; a result in those experiments cannot establish that the abandoned
predictor, fusion sweep or adaptive controller works.

## November stopping decisions

The [candidate matrix](../2026-11-21-integration/candidates.tsv) and
[executive summary](../2026-11-22-research-consolidation/README.md) retain
the November gates and source records. Close the tested packed sparse-Q4
configuration at its request gate and the tested zigzag cutoff at its
perplexity gate. Reopening either requires a cost-changing layout or
dataflow and adequate real-model quality. The measured inactive graph
node and valid terminal-state pruning opportunity closed at their
admission gates. Reopen them for a workflow with a larger measured
complete-request share. The idle-slot KV study requires a different
cache or scheduler ownership model that demonstrably reads idle history.
