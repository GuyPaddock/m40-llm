## Storage-to-attention trace

At `48c6333`, single-sequence mixed direct decode in
[kv.rs](../../src/infer/kv.rs) returns through the existing direct
consumer before looking up staged buffers. With selection diagnostics off,
the Rust wrapper takes the CUDA context lock and passes the cache
handle, sequence ID, query and device output to the asynchronous FFI.
The C launcher in [kernels.cu](../../cuda/kernels.cu) passes the
stored FP16 historical K, recent FP16 K/V, packed historical V and V
scale pointers directly to one decode-stream kernel. Its launch-status
check uses `cudaGetLastError`. There is no host readback, intermediate
global FP16 expansion or device synchronization in this launcher. The
same direct kernel call exists on main `e1403e0`. Other request work,
including cache updates, profile diagnostics and sampling, has its own
synchronization. The broad-grid generation logs record this direct
dispatch on Qwen for both mixed arms.

The staging control needs FP16 K/V, selected positions and per-head counts.
[DecodeSession](../../src/decode_session.rs) allocates this workspace when
`M40LLM_KV_EXACT_BLOCK_STAGING=1` and block-select-exact is active.
Setting that diagnostic flag with direct attention can reserve unused
space. The default leaves it unset. No further default-path staging copy
was found to remove.

The matched operator study uses a research 128-wide staged consumer. The
release runtime admits mixed staged attention only at head width 64.
A full-model comparison therefore uses the supported TinyLlama F16
checkpoint with identical 1,390-token inputs, 1,024 recent positions and
all historical blocks covered. Frozen inputs are at `470f091` on this
branch. The `tiny-kv-consumer` HTTP cohort at `research/1121-consolidation`
`0550ae1` measures actual request wall, CLI, streaming and residency.
Its diagnostic server must emit the expected direct or staged attention
operation in each arm. Its result is independent of the Qwen operator gate.
